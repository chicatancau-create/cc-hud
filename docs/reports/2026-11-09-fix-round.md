## 一、P0（会导致错误结论 / 启动整体失败）

### P0-1 窗口尺寸校验是自证式的
- 位置：`cchud_next/win32.py:205-250`（`place()`）、`cchud_next/host.py:236-259`（`_apply_layout_size`）
- 原状：`place()` 把**自己算出来的请求值**当结果返回，`SetWindowPos` 的返回值从不检查，
  回读 `GetWindowRect` 也没有 → `host.py` 里 `RuntimeError("窗口尺寸未生效")` 这条熔断永远不会触发。
  win32 层坏了，上层也看不出来。
- 修法：`SetWindowPos` 返回值检查 + `GetWindowRect` 回读，`place()` 返回实测 `w/h` 与
  `ok`/`read_ok`/`requested`；`_apply_layout_size` 用实测值比对，`ok is False` 才 raise，
  单纯漂移记 `status["size_mismatch"]` 不 raise（纠回交给矩形守卫，守卫目标仍是请求值）。
- 量纲：`_layout_px` 返回 `int(logical*scale)` 物理像素，与 `GetWindowRect` 同量纲，不会误报。
- 测试：`tests_py/test_size_check.py`、`test_layout_size_drift_is_recorded_not_raised`
- 真机：`runtime.json` → `size_mismatch: null`、`rect: [2014,16,2544,428]`（=424×330 × 1.25 精确）

### P0-2 启动是一个大 try，任一步失败就整体熔断
- 位置：`cchud_next/host.py:453-556`（`_ensure_window_ready`）、`:797-823`（`_wait_hwnd`）
- 原状：`_apply_layout_size` / `apply_settings` / `_start_tray` / `_place_dot` / `ready=True`
  全包在一个 try 里；置顶失败（实测 `host.log` 里 15 次 `RuntimeError('窗口应用失败：置顶设置失败')`）
  会让 `ready` 永远起不来。`_wait_hwnd` 只调一次 `_ensure_window_ready()` 就 return，
  except 里注释说的"让轮询线程还能重试"根本不存在。
- 修法：启动拆成 6 个独立步骤 `js_zoom` / `layout_size` / `window_apply` / `probe` / `tray` / `dot`，
  异常分别进 `status["step_errors"]`；`host_ready` 与外观解耦；只有 `window_apply` 带
  `retry_fn=self._reapply_window`（GUI 线程 + 1.0s 延迟，`_retry_threads` 保证每步仅一次），
  成功记 `step_recovered`、再失败记 `step_retry_failed`；`_wait_hwnd` 失败后继续轮询（0.5s 退避）。
- 并发：`_init_lock` 只包入口守卫（`_initialized`/`_init_started`），`try` 在锁外，
  `except` 里重新取锁也不会死锁（已逐行核对缩进）。
- 测试：`tests_py/test_host_lifecycle.py`、`test_hwnd_failure_is_retryable`
